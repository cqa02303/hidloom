# ADR-NNNN: 決定を表す短い題名

- 状態: 提案中 / 採用済み / 置換済み / 廃止
- 記録日・最終確認日: YYYY-MM-DD
- 決定日: YYYY-MM-DD または不明（遡及記録の場合はその旨）
- 記録対象: 選択肢 / 一般的でない決定 / 見えにくい制約 / 他との関係
- 置換関係: ある場合だけ旧・新ADRへのリンク

## 決定

何をどの範囲で採用・不採用にするか。未実装の案を現行仕様として書かない。

## 理由

判断を左右する核心を原則1〜3文で。過去の理由が確認できない場合は不明とする。

## 代替案・影響

複数の有力案、一般的な方法を採らない理由、他機能との依存など判断に必要な点だけ。
当時検討した事実と、記録時に比較した案・推論を区別する。不要ならこの節は省略できる。

## 現状と再検討条件

採用済み・未実装・部分実装・実機確認待ちを区別し、現行仕様や検証記録へリンクする。
前提が変わると再検討する条件を短く残す。外部割当・実機・versionの古い証跡を最新と扱わない。

## 根拠・関連仕様

確認した仕様、実装、test、決定記録、関連ADRへ実在する相対リンクを置く。
